# Модуль 7. Claude API / SDK для разработчиков

**Поток**: Инженер | **Длительность**: 5 занятий по 90 мин | **Пререквизиты**: Модуль 1,
уверенное владение хотя бы одним языком программирования

## Цели модуля

Студент умеет строить приложения поверх Claude API: базовые вызовы, инструменты,
кэширование, мультимодальный вход, и осознанно выбирать модель под задачу и бюджет.

---

## Занятие 1: Messages API — основы

- Структура запроса: system-промпт, история сообщений, роли
- Потоковая передача (streaming) ответа
- Параметры генерации: температура, максимальная длина, стоп-последовательности
- Обработка ошибок и лимитов запросов

**Практика**: минимальный консольный чат-клиент с потоковым выводом.

## Занятие 2: Tool use

- Определение инструмента: имя, описание, JSON-схема параметров
- Цикл вызова инструментов: модель просит вызов → код исполняет → результат
  возвращается модели → модель продолжает
- Множественные инструменты и выбор между ними
- Structured output через принудительный вызов инструмента

**Практика**: инструмент «получить погоду»/«посчитать выражение», полный цикл
вызова и возврата результата.

## Занятие 3: Prompt caching и оптимизация стоимости

- Что кэшируется и на какое время, почему порядок контента в промпте важен для
  повторного использования кэша
- Экономия на длинных системных промптах/документах, переиспользуемых между
  запросами
- Trade-off: кэш экономит на повторных вызовах, но не бесплатен на первом

**Практика**: посчитать и сравнить стоимость сценария с кэшированием и без для
типового приложения (например, чат-бот с длинной базой знаний в системном промпте).

## Занятие 4: Agent SDK

- Отличие Agent SDK от прямых вызовов Messages API: агентный цикл «из коробки»
- Управляемая песочница (managed sandbox) для выполнения кода/инструментов
- Построение кастомного агента с собственным набором инструментов
- Когда достаточно прямого API, а когда нужен полноценный агентный SDK

**Практика**: собрать простого агента на Agent SDK с 1-2 кастомными инструментами
для конкретной задачи студента.

## Занятие 5: Мультимодальность и выбор модели

- Передача изображений, PDF, документов во входном сообщении
- Ограничения по размеру и формату входа
- Матрица выбора модели: Opus/Sonnet/Haiku/Fable по цене, скорости, качеству —
  как принимать решение для конкретного продукта, а не «просто взять самую мощную»

**Практика**: для 3 разных гипотетических продуктовых сценариев (массовая
классификация, сложный аналитический ассистент, творческий генератор) обосновать
выбор модели.

---

## Итоговый проект модуля

Собственное консольное или веб-приложение на Claude API с минимум одним
инструментом (tool use) и явным обоснованием выбора модели под задачу и бюджет.

## Критерии проверки

- [ ] Приложение корректно обрабатывает цикл вызова инструмента от начала до конца
- [ ] Обработаны базовые ошибки API (лимиты, таймауты)
- [ ] Есть обоснование выбора модели с учётом цены/скорости/качества
- [ ] Студент может объяснить, что и почему кэшируется в его сценарии
