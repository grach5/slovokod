# Модуль 0. Введение и основы промптинга

**Поток**: все | **Длительность**: 1 занятие (90 мин) + домашнее задание | **Пререквизиты**: нет

## Цели модуля

К концу модуля студент умеет:
- объяснить, чем LLM отличается от поисковика или калькулятора;
- выбрать модель Claude под задачу (скорость/цена/качество);
- написать промпт с чёткой ролью, контекстом, форматом и ограничениями;
- распознать типичную галлюцинацию и проверить факт.

## Занятие 1: Как «думает» Claude

### Теория (25 мин)

- **Токены и контекст**: текст режется на токены, модель видит ограниченное «окно» —
  почему длинные документы нужно структурировать, а не просто вставлять целиком.
- **Как рождается ответ**: модель предсказывает следующий токен на основе всего
  предыдущего текста — отсюда важность порядка информации в промпте.
- **Память между сообщениями**: в рамках одного чата — есть контекст, между
  разными чатами — по умолчанию нет (если не подключена память).
- **Линейка моделей**: Opus (макс. качество, дороже/медленнее) → Sonnet (баланс,
  дефолт для большинства задач) → Haiku (быстро и дёшево, для простых
  массовых операций) → Fable (для специфичных творческих сценариев).
  Правило: начинать с Sonnet, повышать до Opus только если качества не хватает.

### Демонстрация (15 мин)

Один и тот же запрос без контекста и с контекстом — сравнение качества ответа.
Пример: «Напиши письмо клиенту» vs «Напиши письмо клиенту Ивану, который жалуется
на задержку заказа на 3 дня, тон — извиняющийся, но без обещания компенсации».

### Практика в парах (30 мин)

Каждая пара получает 3 «плохих» промпта (расплывчатых, без формата, без роли) и
должна переписать их по чек-листу:
1. Роль/аудитория — для кого и от чьего имени
2. Контекст — что уже известно, что приложено
3. Формат вывода — списком, таблицей, письмом, JSON
4. Ограничения — длина, тон, что нельзя упоминать
5. Критерий успеха — как понять, что ответ хороший

### Разбор ошибок (20 мин)

- **Галлюцинации**: модель уверенно выдаёт неверный факт — как проверять
  (перекрёстные источники, прямой вопрос «на чём основан этот вывод»).
- **Переоценка памяти**: студенты часто думают, что Claude «помнит» прошлые
  сессии — показать, что это не так без явного механизма памяти.
- **Итеративность**: один идеальный промпт с первого раза — редкость; норма —
  2-3 уточнения.

## Домашнее задание / мини-проект

Взять реальную рабочую задачу (письмо, план, анализ короткого текста).
Написать первую версию промпта, отправить Claude, оценить ответ по 5 критериям
выше, переписать минимум 2 раза. Сдать: 3 версии промпта + финальный ответ +
короткий вывод (3-4 предложения), что изменилось и почему.

## Критерии проверки

- [ ] В финальном промпте явно заданы роль, контекст, формат, ограничения
- [ ] Есть хотя бы одна итерация с объяснением, что было не так в предыдущей версии
- [ ] Студент указывает, как бы проверил ответ на достоверность
