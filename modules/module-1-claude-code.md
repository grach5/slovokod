# Модуль 1. Claude Code — разработка

**Поток**: Практик / Инженер | **Длительность**: 5 занятий по 90 мин | **Пререквизиты**: Модуль 0, базовые навыки терминала

## Цели модуля

К концу модуля студент умеет: устанавливать и настраивать Claude Code, ориентироваться
в незнакомой кодовой базе, вносить изменения безопасно, писать и запускать тесты,
проводить код-ревью, делегировать часть работы subagents и workflow, тонко
настраивать поведение через permissions/hooks.

---

## Занятие 1: Установка, первый запуск, структура проекта

- Установка CLI, вход в аккаунт, выбор модели по умолчанию
- `CLAUDE.md`: что туда писать (соглашения проекта, команды сборки/тестов, стиль кода)
  и чего избегать (то, что и так видно из кода)
- Режимы разрешений: auto-accept vs подтверждение на каждое действие — когда что уместно
- Структура типичной сессии: запрос → план (при сложных задачах) → выполнение → проверка

**Практика**: установить Claude Code в тестовом репозитории, написать CLAUDE.md с
командами запуска тестов и линтера.

## Занятие 2: Навигация и чтение кода

- Read/Glob/Grep — три инструмента поиска и когда какой использовать
- Разница между «найти файл по паттерну» (Glob) и «найти по содержимому» (Grep)
- Как просить объяснить архитектуру большого проекта, не читая всё вручную
- Работа с Explore-агентом для разведки перед изменением

**Практика**: получить задание «найди, где обрабатывается авторизация» в незнакомом
open-source репозитории и составить карту потока данных.

## Занятие 3: Редактирование, тесты, отладка

- Edit vs Write: точечные правки vs полная перезапись файла
- Правило маленьких диффов: почему просить «одну проблему за раз» эффективнее
- Генерация тестов под существующий код, интерпретация красных тестов
- Итеративная отладка: воспроизвести → локализовать → исправить → проверить

**Практика**: взять баг-репорт, воспроизвести баг, написать падающий тест, исправить,
убедиться что тест зелёный.

## Занятие 4: Git, ревью, subagents

- Коммиты через Claude Code: формат сообщений, что НЕ коммитить
- `/code-review`: уровни эффективности (low/medium/high/ultra), инлайн-комментарии
- Создание PR: заголовок, описание, план тестирования
- Subagents: Explore (только чтение), Plan (архитектура), general-purpose (комплексные
  задачи) — критерий «когда делегировать, а когда делать самому»
- Изоляция через worktree для параллельной работы над несколькими агентами

**Практика**: исправить баг из занятия 3, прогнать `/code-review`, оформить PR с
описанием и планом тестирования.

## Занятие 5: Workflows и настройка поведения

- Когда одного агента недостаточно: фан-аут на независимые части задачи
- pipeline() vs parallel() — разница в конкурентности и когда нужен барьер
- Практический пример: ревью изменений по нескольким независимым критериям параллельно
- `.claude/settings.json`: permissions, hooks, allowlist команд
- Хуки: автоматические проверки при определённых событиях (например, запуск линтера
  после каждого Edit)

**Практика**: настроить allowlist для часто используемых read-only команд проекта,
описать сценарий, где имеет смысл workflow вместо одного агента (без обязательного
реального запуска — это уже billed-функциональность, проговорить это студентам).

---

## Итоговый проект модуля

Взять реальный open-source репозиторий (или рабочий проект студента):
1. Найти и исправить один настоящий баг или добавить небольшую фичу
2. Написать/обновить тесты
3. Провести `/code-review` минимум на уровне `medium`
4. Оформить PR с осмысленным описанием

## Критерии проверки

- [ ] CLAUDE.md в проекте содержит нужные команды и не дублирует то, что видно из кода
- [ ] Дифф маленький и сфокусирован на одной проблеме
- [ ] Есть тест, воспроизводящий баг до исправления
- [ ] PR прошёл код-ревью без критичных замечаний
- [ ] Студент может объяснить, когда стоит делегировать subagent, а когда — нет
