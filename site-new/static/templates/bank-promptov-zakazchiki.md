# Банк промптов: работа с заказчиками

Промпты 61–80. Продолжение [основного банка промптов](pathname:///templates/bank-promptov.md).
Только в тарифе «Максимум». Тема одна: как превращать навык в первые заказы.

## Поиск и оценка работы

**61. Где искать первые заказы**
```
Я умею собирать: [список типов продуктов].
Живу в [город/страна], опыта в разработке нет,
портфолио: [сколько проектов].

Перечисли пять конкретных мест, где такие задачи
встречаются чаще всего, от самого доступного новичку.
По каждому скажи, что там ждут в отклике.
Без общих советов вроде «развивай личный бренд».
```

**62. Кому нужна моя услуга**
```
Я собираю [что именно].
Перечисли пять типов бизнеса, у которых эта задача
возникает регулярно, и по каждому — как эта проблема
звучит их словами, а не техническими терминами.
```

**63. Оценка заказа в часах**
```
Заказчик хочет: [описание].
Разбей на этапы, оцени каждый в часах для человека
без опыта в разработке, добавь запас на непредвиденное.
Отдельно: что в описании непонятно и что уточнить
до начала.
```

**64. Стоит ли браться**
```
Заказ: [описание]. Бюджет: [сумма]. Срок: [срок].
Я умею: [список].

Скажи честно: реалистично ли это для меня.
Что может пойти не так. Какие три вопроса задать,
чтобы понять, браться или нет.
Не подбадривай.
```

**65. Цена работы**
```
Работа: [описание], оценка [часов].
Мой уровень: [опыт], рынок: [страна/город].

Предложи три варианта цены: осторожный, обычный,
уверенный. По каждому скажи, чем он обоснован
и что должно быть в моём портфолио, чтобы просить именно столько.
```

## Общение с заказчиком

**66. Вопросы до начала**
```
Составь список вопросов заказчику по задаче:
[описание].
Только те, без ответа на которые нельзя начинать.
Не больше десяти. Формулируй так, чтобы понял человек
без технического опыта.
```

**67. Задание для заказчика**
```
Преврати это в задание, понятное человеку
без технического опыта.
Обязательные разделы: что делаем, что получится
в итоге, срок, что НЕ входит в работу.
[описание]
```

**68. Границы работы**
```
По этой задаче перечисли, что заказчики обычно
ожидают по умолчанию, но что в работу не входит.
Нужно, чтобы прописать явно и не спорить потом.
[задача]
```

**69. Клиент просит доделать сверх задания**
```
Сдал работу по заданию. Заказчик просит добавить:
[что].
Помоги написать ответ: доброжелательно, без конфликта,
с объяснением, что это отдельная работа,
и с предложением оценить её отдельно.
```

**70. Перенос срока**
```
Работа займёт больше времени, причина: [какая].
Напиши сообщение заказчику: без оправданий,
с новым сроком, с перечислением того, что уже готово.
Коротко.
```

**71. Заказчик пропал**
```
Заказчик не отвечает [сколько] дней, работа
на этапе [какой], оплачено [сколько].
Напиши сообщение, которое не давит, но обозначает,
что работа приостановлена и что будет дальше.
```

**72. Правки без конца**
```
Заказчик прислал [номер] раунд правок,
в задании было [что].
Помоги обозначить границу: сколько правок входит
в работу, что дальше платно. Без обвинений.
```

## Сдача и передача

**73. Что передать при сдаче**
```
Сдаю проект: [описание].
Составь список того, что передать заказчику:
доступы, файлы, инструкции.
Отдельно — короткая инструкция «что делать,
если что-то сломается».
```

**74. Инструкция для заказчика**
```
Напиши инструкцию по пользованию продуктом
для человека без технического опыта.
Только то, что ему реально понадобится.
Не больше одной страницы, по шагам.
[описание продукта]
```

**75. Договорённость о поддержке**
```
Помоги сформулировать условия поддержки после сдачи:
что входит бесплатно и сколько времени, что платно.
Коротко, понятным языком, чтобы вставить в переписку.
Работа: [описание].
```

## Портфолио и повторные продажи

**76. Кейс из проекта**
```
Преврати проект в описание кейса.
Разделы: задача, что сделано, как сделано, сроки,
ссылки, что бы сделал иначе.
Без преувеличений, честные сроки, без слова
«уникальный».
[описание проекта]
```

**77. Пост о своей работе**
```
Напиши пост о том, как я собрал [что].
Структура: с какой задачей пришли, что было сложным,
что получилось, одна честная ошибка.
Без хвастовства и без призывов.
В конце — одна строка, что беру такие задачи.
```

**78. Просьба об отзыве**
```
Помоги написать заказчику просьбу об отзыве
после успешной сдачи.
Коротко, без навязчивости, с тремя конкретными
вопросами, на которые ему легко ответить.
```

**79. Предложение следующей работы**
```
Сдал заказчику [что]. Вижу, что ему пригодилось бы
ещё и [что].
Помоги предложить это так, чтобы не выглядело
как навязывание: от его задачи, а не от моего желания
продать.
```

**80. Разбор неудачи**
```
Проект пошёл не так: [что случилось].
Разбери: что было в моей зоне ответственности,
что нет, что сделать иначе в следующий раз.
Отдельно — какой пункт добавить в задание,
чтобы это не повторилось.
Без утешений.
```
