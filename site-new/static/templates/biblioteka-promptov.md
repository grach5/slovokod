# Стартовая библиотека промптов

Оригинальный набор рабочих промптов на каждый день — не как готовые ответы, а
как каркас, который вы адаптируете под свою задачу. Разбито по темам курса.

## Промптинг и письмо (M0)

**Письмо клиенту / коллеге**
```
Напиши письмо [кому, в каком тоне: формально/дружелюбно].
Контекст: [что произошло].
Нужно донести: [1-3 пункта].
Не упоминать: [что важно не обещать/не говорить].
Объём: [N предложений].
```

**Анализ документа**
```
Проанализируй [документ/отчёт]: выдели [N] главных [трендов/проблем/выводов].
Сравни с [база для сравнения, если есть].
Формат ответа: буллеты, не длиннее [N] слов.
```

## Код и отладка (M1)

**Найти и исправить баг**
```
Воспроизведи баг: [шаги/симптом].
Найди корневую причину, не просто симптом.
Предложи минимальный фикс — один дифф, одна проблема.
Добавь тест, который падал бы до исправления.
```

**Код-ревью перед мержем**
```
Проведи код-ревью этого диффа на уровне [low/medium/high].
Проверь: корректность, побочные эффекты в других слоях, покрытие тестами,
потенциальные уязвимости.
Не предлагай рефакторинг за рамками этого диффа.
```

## Автоматизация и агенты (M2)

**Регулярная проверка источника**
```
Раз в [период] проверяй [источник данных].
Если есть значимые изменения — присылай сводку в формате [N] буллетов.
Если изменений нет — ничего не присылай.
При сбое источника: повтори через [N] минут, затем сообщи явно об ошибке.
```

## Документы и отчёты (M3)

**Очистка «грязных» данных**
```
Вот сырой экспорт: [вставить/приложить].
Почисти: убери пустые строки/колонки, приведи формат [дат/чисел/валют] к
единому виду, не меняя исходные значения по смыслу.
Верни как чистую таблицу, готовую для отчёта.
```

## Исследования (M5)

**Исследовательский отчёт с источниками**
```
Собери 4+ проверяемых источника по теме: [тема].
Для каждого факта укажи источник и дату.
Явно отметь, где источники противоречат друг другу.
Не выдавай предположения за проверенные данные.
```

## Токены и память (M2.5)

**Обновление memory-bank**
```
Обнови activeContext.md и progress.md на основе этой сессии:
- что сделано
- что осталось открытым вопросом
- что делать в следующий раз
Не переписывай productContext.md и decisionLog.md, если не было архитектурных
решений.
```

---

Это стартовый набор — расширяйте его собственными рабочими промптами по мере
того, как находите формулировки, которые стабильно дают хороший результат.
