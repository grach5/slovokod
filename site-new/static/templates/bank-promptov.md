# Банк промптов «Словокод»

60 рабочих запросов, сгруппированных по задачам — не готовые ответы, а каркасы,
которые вы адаптируете под свою задачу. Квадратные скобки заменяйте своим текстом.

Промпты из «Постановка задачи», «Внешний вид» и «Проверка и приёмка» пригодятся
уже в треке «База». Разделы «Данные и безопасность» и часть «Отладки»
(публикация, работает локально/не в интернете) требуют базы данных и хостинга —
это трек «Полная», начиная с Дня 8.

## Постановка задачи

**1. Разбор задания перед работой**
```
Ниже техническое задание. Сначала перескажи его своими словами
и задай вопросы по всем местам, где есть неоднозначность.
Код не пиши, пока я не отвечу.
[задание]
```

**2. Превратить идею в задание**
```
Помоги превратить идею в техническое задание.
Идея: [описание].
Задай мне по одному вопросу за раз, пока не соберёшь:
что это, кто пользуется, шаги пользователя, что сохраняется,
ограничения, критерии готовности.
Не предлагай решений, только собирай информацию.
```

**3. Проверить задание на дыры**
```
Прочитай задание и перечисли всё, что в нём не описано
и что тебе пришлось бы додумывать. Ничего не додумывай,
просто дай список пропусков.
[задание]
```

**4. Сформулировать критерии готовности**
```
Из этого описания сделай список критериев готовности.
Каждый критерий должен проверяться ответом «да» или «нет»
и описывать то, что видно на экране.
Слова «удобно», «красиво», «быстро» не использовать.
[описание]
```

**5. Разбить на шаги**
```
Разбей задачу на 5–7 шагов.
Порядок: сначала каркас, потом действия, потом данные,
потом внешний вид.
Для каждого шага укажи, что должно появиться на экране,
чтобы шаг считался выполненным.
Код не пиши.
[задача]
```

**6. Один шаг в работу**
```
Мы собираем проект по шагам. Общее описание ниже — оно нужно
только для понимания направления.
[файл проекта]

Сейчас сделай ТОЛЬКО ЭТО: [шаг]
Готово считается так: [критерий]
Не добавляй ничего сверх описанного, не улучшай оформление,
не добавляй функции на будущее.
Выдай готовый код одним блоком.
```

**7. Оценить объём**
```
Сколько примерно шагов и времени займёт эта задача
для человека без опыта в программировании?
Раздели на «сегодня можно», «нужен отдельный день»,
«пока не браться».
[задача]
```

**8. Упростить задачу**
```
Эта задача кажется мне слишком большой.
Предложи минимальную версию, которая всё ещё полезна.
Что можно выбросить без потери смысла?
[задача]
```

## Работа с кодом

**9. Первый вариант**
```
Сделай [что нужно].
Требования: [список]
Ограничения: минимум файлов, без внешних библиотек,
самое простое рабочее решение.
Выдай только код одним блоком, без объяснений.
```

**10. Минимальная правка**
```
Нужно изменить только одно: [что].
Не трогай ничего остального.
Покажи, какие строки меняются, и выдай только изменённый фрагмент.
```

**11. Объяснить, что делает код**
```
Объясни, что делает этот код, простыми словами,
как человеку без опыта в программировании.
Пять предложений максимум. Без терминов,
а если термин необходим — расшифруй в скобках.
[код]
```

**12. Что здесь лишнее**
```
Посмотри код и скажи, что в нём лишнее:
неиспользуемое, дублирующееся, добавленное «на будущее».
Ничего не удаляй, дай список с указанием строк.
```

**13. Сделать проще**
```
Упрости этот код, сохранив поведение полностью.
Цель — чтобы новичок мог прочитать и понять.
Покажи, что изменилось и почему.
```

**14. Спросить перед добавлением**
```
Если для этой задачи нужна дополнительная библиотека —
сначала скажи какая и зачем, и предложи вариант без неё.
Не добавляй ничего без моего согласия.
```

**15. Собрать в один файл**
```
Собери всё в один файл. Стили и логику помести внутрь.
Внешних зависимостей быть не должно.
```

**16. Разбить один файл**
```
Файл стал слишком большим. Предложи, как разбить его
на части по смыслу. Сначала план, код после моего согласия.
```

## Отладка

**17. Основной запрос по ошибке**
```
[карточка ошибки целиком]

Найди причину. Предложи ОДНО минимальное изменение.
Не переписывай файлы целиком. Не улучшай ничего попутно.
Если причин может быть несколько — перечисли и скажи,
как отличить одну от другой.
```

**18. Ошибка при запуске**
```
Проект не запускается. Вот вывод терминала целиком:
[текст]
Скажи одной строкой, в чём причина, и дай точные действия.
```

**19. Ошибка публикации**
```
Публикация не удалась. Текст из журнала целиком:
[текст]
Причина и список действий. Не предлагай менять то,
что не относится к этой ошибке.
```

**20. Работало вчера**
```
Вчера работало, сегодня нет. Я менял: [что].
Вот текст ошибки: [текст]
Скажи, что из моих изменений могло это вызвать.
```

**21. Работает локально, не работает в интернете**
```
На компьютере работает, на опубликованном сайте нет.
Ошибка: [текст]
Перечисли типичные причины такого расхождения
и как проверить каждую.
```

**22. Плавающая ошибка**
```
Ошибка появляется не всегда. Когда появляется: [когда].
Когда не появляется: [когда].
Что общего в случаях появления? Как это проверить?
```

**23. Сузить поиск**
```
Не понимаю, где именно ломается.
Предложи способ проверить по частям: что вывести на экран
и в каком порядке, чтобы найти место поломки.
```

**24. Начать с чистого листа**
```
Мы третий раз чиним одно и то же и ходим по кругу.
Забудь предыдущие гипотезы.
Вот факты: [карточка ошибки]
Дай три версии причины, от самой вероятной,
и способ проверить каждую за одну минуту.
```

## Данные и безопасность

**25. Спроектировать таблицу**
```
Помоги спроектировать таблицу для хранения [чего].
Предложи поля, типы, что обязательно.
Скажи, какие поля я, скорее всего, забыл.
Код не пиши.
```

**26. Подключить базу**
```
Подключи базу для сохранения [чего].
Поля: [список], обязательные: [список].
Требования:
— адрес и ключ берутся из .env, в коде их нет
— форма проверяет обязательные поля до отправки
— после отправки показывается подтверждение
— при ошибке показывается человеческое сообщение
Сначала перечисли, какие файлы изменишь и что положить в .env.
Код после моего подтверждения.
```

**27. Настроить права доступа**
```
Объясни простыми словами, как настроить права доступа
к таблице так, чтобы добавлять записи мог кто угодно,
а читать только я. Продиктуй значения по пунктам,
как их вводить в интерфейсе.
```

**28. Найти секреты в коде**
```
Проверь проект на секреты. Перечисли файлы и строки,
где встречаются ключи, пароли, токены, строки подключения.
Ничего не исправляй, дай список.
Затем скажи, как вынести найденное в переменные окружения.
```

**29. Вынести ключи**
```
Вынеси все ключи в переменные окружения.
Дай: содержимое .env.example, список изменённых файлов,
и что прописать в настройках сервиса публикации.
```

**30. Проверка по чек-листу**
```
Проверь проект по списку и по каждому пункту ответь
«выполнено» или «не выполнено» с указанием файла и строки.
Ничего не исправляй.
[пятнадцать пунктов чек-листа из Дня 12]
После списка предложи порядок исправления:
от самого опасного к наименее важному.
```

**31. Проверка ввода**
```
Добавь проверку данных, которые приходят в [куда].
Проверять: обязательность, длину, формат.
При неверных данных — понятное сообщение пользователю,
техническую информацию не показывать.
```

**32. Ограничить частоту**
```
Добавь ограничение: не более [N] отправок формы
с одного устройства за [время].
Простейшее рабочее решение, без дополнительных сервисов.
```

## Внешний вид

**33. Оформление по описанию**
```
Оформи страницу так:
— фон: [какой]
— основной цвет: [какой]
— одна колонка по центру, максимальная ширина [N] пикселей
— крупный заголовок, читаемый основной текст
— кнопка заметная, с изменением при наведении
Логику не трогай.
```

**34. Адаптировать под телефон**
```
Сделай так, чтобы страница нормально выглядела на телефоне:
ничего не разъезжается, текст читается без увеличения,
кнопки нажимаются пальцем.
Внешний вид на компьютере не меняй.
```

**35. Что не так с версткой**
```
Вот как страница выглядит на телефоне: [описание или скриншот].
Перечисли, что именно не так, и предложи исправления
по одному, от самого заметного.
```

**36. Состояния интерфейса**
```
Добавь понятные состояния: загрузка, пусто, ошибка, успех.
Для каждого — что видит пользователь.
Технических деталей в текстах быть не должно.
```

## Публикация и запуск

**37. Подготовить к запуску**
```
Подготовь проект к локальному запуску.
Дай: список файлов, их содержимое, точные команды по порядку.
Команды отдельно для Windows и macOS.
Каждую команду объясни одной строкой.
Если нужно что-то установить — скажи, что именно
и с какого официального сайта.
```

**38. Подготовить к публикации**
```
Что нужно сделать, чтобы опубликовать проект в интернете?
Дай список действий по порядку.
Отдельно перечисли, какие переменные окружения
нужно завести в настройках сервиса.
```

**39. Написать README**
```
Напиши README для проекта.
Структура: название и одно предложение о продукте, для кого,
что умеет (3–5 пунктов), как запустить (команды по порядку),
из чего собрано.
Коротко, без воды, без эмодзи. Формат Markdown.
Описание проекта: [файл проекта]
```

**40. Подписи к точкам сохранения**
```
Я сделал: [что].
Предложи короткую подпись к точке сохранения,
которая описывает состояние проекта, а не действие.
```

## Проверка и приёмка

**41. Что проверить перед показом**
```
Я собираюсь показать проект другому человеку.
Составь список того, что проверить перед этим,
с точки зрения человека, который видит продукт впервые.
```

**42. Найти слабые места**
```
Посмотри на проект глазами недоброжелательного пользователя.
Что он сломает первым делом? Перечисли пять вещей
и что с каждой сделать.
```

**43. Крайние случаи**
```
Перечисли крайние случаи для этой формы:
пустые значения, очень длинные, спецсимволы, повторная отправка.
Для каждого скажи, что должно происходить.
```

**44. Проверить самому себе**
```
Задай мне пять вопросов по моему проекту,
чтобы проверить, понимаю ли я, как он работает.
Вопросы про устройство и поведение, не про синтаксис.
```

## Обучение и разбор

**45. Объясни термин**
```
Объясни, что такое [термин], человеку без технического опыта.
Три предложения, один бытовой пример.
```

**46. Зачем это нужно**
```
Зачем в моём проекте нужен [что]?
Что будет, если этого не делать? Ответь конкретно
про мой случай, не в общем.
```

**47. Разбери мою ошибку**
```
Я сделал: [что]. Получилось не то.
Объясни, где именно я ошибся в постановке задачи,
и как надо было сформулировать.
```

**48. Что я не знаю**
```
Вот мой проект: [описание].
Перечисли пять вещей, которых я, скорее всего,
не знаю и которые важны для этого типа продукта.
По каждой — одно предложение, почему это важно.
```

**49. План на неделю**
```
Мне непонятна тема: [что].
Составь план разбора на неделю: по одному действию в день,
не больше часа в день, каждое действие с проверяемым результатом.
```

**50. Второй проект**
```
Я собрал [что было]. Хочу второй проект, чуть сложнее,
но той же природы, чтобы закрепить навык.
Предложи три варианта и скажи, чем каждый сложнее первого.
```

## Работа с заказчиками (введение)

Промпты 51–60 — базовый набор для первых заказов. Более широкий набор
(промпты 61–80 — поиск заказов, ценообразование, сложные переговоры)
входит в [банк промптов для работы с заказчиками](pathname:///templates/bank-promptov-zakazchiki.md)
(тариф «Максимум»).

**51. Оценить заказ**
```
Заказчик хочет: [описание].
Разбей на этапы, оцени каждый в часах для человека
моего уровня, добавь запас на непредвиденное.
Скажи, что в описании заказчика непонятно
и что нужно уточнить до начала.
```

**52. Вопросы заказчику**
```
Составь список вопросов заказчику по этой задаче.
Только те, без ответа на которые нельзя начинать.
Не больше десяти.
```

**53. Техническое задание для заказчика**
```
Преврати это в техническое задание, понятное заказчику
без технического опыта. Обязательно раздел
«что не входит в работу».
[описание]
```

**54. Что не входит в работу**
```
По этой задаче перечисли, что обычно ожидают заказчики,
но что не входит в работу по умолчанию.
Это нужно, чтобы прописать явно.
[задача]
```

**55. Объяснить задержку**
```
Помоги написать сообщение заказчику: работа займёт
больше времени, потому что [причина].
Без оправданий, с новым сроком и с тем,
что уже готово.
```

**56. Передать проект**
```
Составь список того, что передать заказчику
при сдаче: доступы, файлы, инструкции, что он должен
сделать сам. Отдельно — что делать, если что-то сломается.
```

**57. Описать кейс**
```
Преврати этот проект в описание кейса для портфолио.
Структура: задача, что сделано, как сделано, сроки, ссылки,
что бы сделал иначе.
Без преувеличений, честные сроки.
[описание проекта]
```

**58. Оценить, браться ли**
```
Заказчик предлагает: [описание], бюджет [сколько],
срок [какой].
Скажи честно: реалистично ли это для человека,
который [ваш уровень]. Какие риски. Что уточнить.
```

**59. Разобрать неудачу**
```
Проект пошёл не так: [что случилось].
Разбери: что было в моей зоне ответственности,
что нет, и что сделать иначе в следующий раз.
Без утешений.
```

**60. Следующий шаг**
```
Вот что я умею: [список].
Вот что я сделал: [проекты].
Какой один навык добавит больше всего пользы прямо сейчас
и почему именно он? Дай план освоения на две недели.
```
