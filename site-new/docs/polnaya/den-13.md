## Зачем это

До сегодня вы работали в чате: попросили код, вставили в файл, проверили сами.
Это надёжно, но медленно — на каждую мелкую правку уходит несколько минут.
Представьте, что нужно поменять один и тот же блок на десяти страницах сайта.
Руками — десять раз одно и то же. Хочется, чтобы ассистент делал это сам.
Сегодня вы включаете агентный режим (assistant сам работает с файлами проекта), и скорость растёт в разы.

## Что вы сделаете

Настроите агентный режим работы с проектом и автоматизируете одну реальную повторяющуюся задачу.

## Главное правило

**Перед запуском агента всегда сохраняйте точку возврата. Агент может изменить двадцать файлов за минуту — без точки восстановления разбирать это придётся руками.** Поэтому агентный режим идёт после дня про откаты, а не до него.

## Теория

В чате ассистент отдаёт вам текст, а вы сами вставляете его в файл. В агентном режиме (agent mode) ассистент открывает файлы проекта сам, вносит изменения, запускает команды — а вы подтверждаете или отклоняете каждый шаг.

Чтобы не повторять одни и те же требования в каждом запросе, их выносят в отдельный файл правил проекта. Ассистент читает этот файл автоматически при каждой задаче. Туда идёт то, что вы иначе писали бы заново: «не трогай эти файлы», «сначала покажи, что изменишь», «секреты только из .env».

Есть два режима подтверждения. Первый — спрашивать перед каждым изменением файла. Второй — действовать самостоятельно, без остановки. Разница ощутима: самостоятельный режим экономит минуты на рутине, но одна незамеченная ошибка может стоить часов на разбор. Поэтому первый месяц работы — только с подтверждением каждого шага.

Автоматизировать в первую очередь стоит то, что вы уже делали руками несколько раз: однотипные правки в разных файлах, приведение файлов к одному виду, добавление одинакового блока на несколько страниц, перенос данных из одного формата в другой.

Инструмент для агентного режима подходит любой, умеющий работать с папкой проекта напрямую — методика одна и та же для любого ИИ-ассистента. Для дней с терминалом в этом курсе вы уже пользовались Claude Code (Anthropic) — он умеет работать и в агентном режиме, поэтому дальше в шагах речь идёт о нём, но подойдёт и другой похожий инструмент.

Дальше вы соберёте файл правил, включите подтверждение каждого шага и дадите ассистенту первую небольшую задачу.

## По шагам

1. Сохраните точку в системе версий (как в дне про откаты). Вы должны увидеть: новая точка появилась в истории проекта.

2. Убедитесь, что точка отправлена на GitHub. Вы должны увидеть: последний коммит виден в репозитории на GitHub.

3. Установите инструмент с агентным режимом, например Claude Code. Вы должны увидеть: инструмент запускается и открывает командную строку.

4. Откройте папку проекта в этом инструменте. Вы должны увидеть: инструмент видит файлы вашего проекта.

5. Создайте файл правил проекта по шаблону из следующего блока. Вы должны увидеть: файл с разделами «Всегда», «Никогда» и «О проекте».

6. Убедитесь, что включён режим подтверждения каждого изменения. Вы должны увидеть: в настройках инструмента выбран режим «спрашивать перед изменением», а не «действовать самостоятельно».

7. Дайте ассистенту первую задачу — небольшую, из тех, что вы уже делали руками. Вы должны увидеть: ассистент показывает план или сразу первое предлагаемое изменение.

8. Просмотрите каждое предложенное изменение до подтверждения, не подтверждайте пачкой. Вы должны увидеть: по каждому файлу отдельный запрос на подтверждение, и вы понимаете, что именно меняется.

9. Проверьте результат и сохраните новую точку. Вы должны увидеть: задача выполнена так же, как вы делали её руками, и точка сохранена.

10. Выберите одну повторяющуюся задачу, которую делали руками больше трёх раз, и автоматизируйте её через агента. Вы должны увидеть: задача выполнена агентом от начала до конца, с вашими подтверждениями.

11. Сравните, сколько времени задача занимала раньше и сколько заняла с агентом. Вы должны увидеть: две цифры — время руками и время с агентом.

## Готово к копированию

```
# ПРАВИЛА ПРОЕКТА

## Всегда
- Минимальные изменения — только по задаче.
- Перед изменением файла показать, что именно меняется.
- Секреты только из .env.
- После изменения сказать, как проверить результат.

## Никогда
- Не менять файлы, не относящиеся к задаче.
- Не добавлять библиотеки без согласия.
- Не переписывать рабочий код ради стиля.
- Не трогать: [перечислить файлы]

## О проекте
[вставить ПРОЕКТ.md]
```

```
Вот моя первая задача для агентного режима: [опишите задачу, которую вы уже делали руками и знаете правильный результат]. Работай по файлу правил проекта. Перед каждым изменением файла покажи, что именно меняется, и жди моего подтверждения. Не трогай файлы, не относящиеся к задаче. В конце скажи, как проверить результат.
```

## Типичные ошибки

- В проекте двадцать изменённых файлов, непонятно, что было раньше → точка не сохранена перед запуском → всегда сохраняйте и отправляйте точку до первого запуска агента.
- Через неделю в проекте код, о котором вы не знаете → изменения подтверждали пачкой, не глядя → просматривайте каждое изменение по отдельности.
- Результат агента непредсказуем, правки не те → первая задача была слишком большая → начните с задачи, которую уже делали руками и знаете правильный результат.
- Одни и те же замечания повторяются в каждом запросе → нет файла правил проекта → создайте файл с разделами «Всегда» и «Никогда».
- Месяц ушёл на разбор случайных правок → самостоятельный режим включили слишком рано → первый месяц работайте только с подтверждением каждого шага.

## Задание и критерии приёмки

- [ ] Точка сохранена и отправлена на GitHub до первого запуска агента.
- [ ] Файл правил проекта создан, содержит разделы «Всегда» и «Никогда».
- [ ] Включён режим подтверждения каждого изменения.
- [ ] Каждое изменение просмотрено до применения, без подтверждения пачкой.
- [ ] Автоматизирована реальная повторяющаяся задача, а не выдуманная.
- [ ] Указано, сколько времени задача занимала раньше и сколько занимает теперь.

Сдаёте: файл правил проекта, описание автоматизированной задачи, сравнение времени.

## Если не получилось

- Агент меняет файлы, не относящиеся к задаче → дополните раздел «Никогда» конкретными именами файлов, перезапустите задачу с чистого состояния.
- Предложенных изменений слишком много, чтобы просмотреть каждое → задача была великовата → откатитесь к сохранённой точке и разбейте задачу на меньшую.
- Не находится, что автоматизировать → посмотрите, какие действия вы за курс повторяли руками больше трёх раз.
