**Пререквизиты**: Модуль 2

Модуль 2 научил подключать агента к внешним системам и запускать его без вас. Разница между «человеком, который пишет промпты» и специалистом, который проектирует работу с таким агентом на дистанции, сводится к одному навыку: управлению контекстом и токенами.

## 1. Почему это важно

У раздутого контекста три цены:

| Цена | В чём проявляется |
|---|---|
| Деньги | Каждый токен контекста оплачивается при каждом запросе — включая старые файлы и логи, не нужные модели |
| Задержка | Чем длиннее контекст, тем дольше модель его обрабатывает до начала ответа |
| Качество (главное) | Смесь актуальных требований, устаревших планов и логов мешает модели отличить сигнал от шума |

Цель — не «контекст поменьше», а контекст, где каждая строчка оправдывает своё место.

## 2. Паттерн memory-bank

Внятное решение предложил проект **RooFlow** (GreatScottyMac/RooFlow) для Roo Code, расширения VS Code для агентов. Мы не копируем их файлы, а адаптируем идею под Claude — она переносится на любой инструмент.

Идея: вместо бесконечно растущего чата агент ведёт папку `memory-bank/` — markdown-файлы с разделённой ответственностью. В начале сессии агент читает их вместо того, чтобы «вспоминать» контекст из истории. Перед закрытием сессии нужные файлы обновляются — это момент «Update Memory Bank» (термин «Update Memory Bank» — название этого шага в оригинальном RooFlow; в Claude Code это просто обычное редактирование .md-файлов, отдельной команды вводить не нужно).

| Файл | Роль | Как часто меняется |
|---|---|---|
| `productContext.md` | Общая картина: что за проект, для кого, ограничения | Редко — «конституция» проекта |
| `activeContext.md` | Что происходит сейчас: фокус, открытые вопросы, блокеры | Почти каждую сессию |
| `decisionLog.md` | Решения с обоснованием — *что* и, обязательно, *почему* | По факту решения |
| `progress.md` | Сделано / в работе / запланировано | Регулярно |
| `systemPatterns.md` *(опц.)* | Конвенции проекта: неймспейсы, стиль коммитов, выбор библиотек | Редко |

Ключевое свойство — точечность обновлений: приняли решение — строка в `decisionLog.md`, сдвинулась задача — абзац в `activeContext.md`. Дешевле по токенам и не затирает то, что ещё актуально.

В Claude Code аналог паттерна — `CLAUDE.md` плюс то, как устроены сессии: каждая сессия начинается со свежего контекста, в который вы сами подгружаете только нужное. Логика та же — разделяй по ролям, обновляй точечно.

## 3. Шаблон: пример папки memory-bank

Компактный пример для вымышленного проекта — телеграм-бота учёта расходов «Копилка»:

```
memory-bank/
├── productContext.md
├── activeContext.md
├── decisionLog.md
├── progress.md
└── systemPatterns.md
```

**`productContext.md`**
```markdown
# Копилка — бот учёта расходов

Телеграм-бот: пользователь пишет "кофе 250", бот раскладывает по категориям
и раз в неделю присылает сводку. Целевая аудитория — фрилансеры без бухгалтера.

Стек: Python, aiogram, SQLite (на старте), деплой на один VPS.
Не делаем: мультивалютность и командную работу — это следующая версия, не MVP.
```

**`activeContext.md`**
```markdown
# Текущий фокус (обновлено 2026-07-20)

Работаем над: парсингом свободного текста в сумму + категорию.
Открытый вопрос: "такси домой 600" — одна категория или два триггера?
Пока эвристика берёт первое совпадение.

Заблокировано: нет единого логгера ошибок — сбои парсинга падают в консоль,
а не пользователю. Отложено до следующей сессии.
```

**`decisionLog.md`**
```markdown
# Решения

## 2026-07-14 — SQLite вместо Postgres на старте
Проект соло, нагрузка не выше нескольких сотен сообщений в день.
Postgres добавил бы деплой-сложность без реальной пользы на этом этапе.

## 2026-07-18 — Категории — фиксированный список, не свободный ввод
Свободные категории давали неконсистентные сводки в тестах.
Фиксированный список из 8 категорий + "другое" проще парсить и агрегировать.
```

**`progress.md`**
```markdown
# Статус

Готово: приём сообщений, сохранение в БД, недельная сводка текстом.
В работе: парсинг суммы+категории из текста (см. activeContext).
Далее: экспорт в CSV, обработка голосовых (озвучено, не начато).
```

**`systemPatterns.md`**
```markdown
# Паттерны проекта

Коммиты: Conventional Commits (feat/fix/chore).
Хэндлеры aiogram — по файлу в handlers/, без логики внутри — только вызов сервиса.
Тесты — pytest, обязательны для парсера сумм (самая хрупкая часть).
```

Ни один файл не пересказывает остальные — вместе они дают полную картину быстрее, чем один длинный файл с историей чата.

## 4. Специфичные для Claude приёмы экономии

- **Промпт-кэширование.** Anthropic API кэширует повторяющиеся части запроса (системный промпт, статичный документ, список инструментов) — переиспользование дешевле полной цены. Проценты экономии из маркетинга — заявления вендора для конкретного сценария, не универсальный факт. Проверяйте на своей задаче.
- **Лаконичный `CLAUDE.md`.** Не превращайте его в архив всего важного. Оставьте только то, что верно всегда: стиль кода, команды сборки/тестов, структура репозитория. Остальное — отдельным файлом со ссылкой.
- **Разделение планирования и реализации.** Сессия «план → код → отладка → снова план» копит противоречивый контекст. Закрывайте планирование отдельным файлом (`activeContext.md`/`progress.md`), реализуйте в свежем контексте.
- **Выбор модели как рычаг стоимости.** Haiku — объёмные несложные задачи (классификация, извлечение данных). Sonnet — основная рабочая лошадка. Opus — задачи с реальной глубиной рассуждения. Opus там, где хватило бы Haiku, — растрата бюджета «на всякий случай».

## 5. Практика

Постройте для своего проекта папку `memory-bank/` по образцу из раздела 3:

1. Заполните `productContext.md` — 3–5 предложений, без деталей реализации.
2. Заполните `activeContext.md` реальным статусом: над чем работаете, что открыто/заблокировано.
3. Найдите решение, принятое «на ходу» и нигде не зафиксированное, — оформите в `decisionLog.md` с явным «почему».
4. Дайте эти файлы Claude вместо пересказа контекста — сравните скорость выхода на нужный уровень понимания.

## 6. Чек-лист: признаки нездорового контекста

| Признак | Что это значит | Как чинит memory-bank |
|---|---|---|
| Каждую сессию заново объясняете, что за проект и какие правила | Нет зафиксированного верхнего контекста | `productContext.md` читается один раз |
| Никто не помнит, почему приняли решение | Решения потерялись в чате | `decisionLog.md` с обязательным «почему» |
| `CLAUDE.md` разросся на сотни строк, его никто не перечитывает | Файл стал свалкой | Только то, что верно всегда; остальное — по ссылке |
| Агент «забывает» задачу, предлагает отклонённое | Смешаны актуальное и устаревшее | Разделение план/реализация + свежий `activeContext.md` |
| Счёт за API растёт без роста сложности задач | Токены уходят на нерелевантный контекст | Точечные апдейты памяти + кэширование статичных блоков |
| Одна модель для простой классификации и сложной архитектуры | Выбор модели не учитывает сложность | Haiku — объём, Sonnet — основное, Opus — сложное |
