## Зачем это

Вчера всё получилось с первого раза. Сегодня ассистент выдал что-то не то — и непонятно, почему.
Кажется, что результат — лотерея: повезёт или нет.
На самом деле это не случайность. У поведения ассистента есть механика — три правила.
Пока вы их не знаете, каждая неудача выглядит как сбой.
Как только знаете — вы видите причину и чините её за секунды.

## Что вы сделаете

Соберёте страницу-визитку промптом в Claude и внесёте в неё 3 изменения.
Результат: рабочий цикл «попросил → вставил → проверил», который будете использовать весь курс.

## Главное правило

**Ассистент не помнит вас и не понимает задачу — он видит только текст перед собой и продолжает его наиболее вероятным образом.** Это не собеседник с памятью и намерениями, а система продолжения текста. Отсюда все три механизма ниже — и все типичные ошибки новичков.

## Теория

Из главного правила следуют три механизма.

**1. Контекст — это рабочий стол, а не память.** Переписка с ассистентом (в Claude — как и в любом другом ассистенте) хранится не бесконечно: разговор растёт, и старое перестаёт помещаться в поле зрения модели. Поэтому важные условия задачи повторяют заново, а не считают сказанным «навсегда».

**2. Модель достраивает задачу, а не уточняет её.** Если в описании есть пробел (например, вы не указали цвет кнопки), ассистент не остановится и не спросит — он заполнит пробел типичным вариантом. Не обязательно тем, что вы имели в виду. Неопределённость в промпте решается не в вашу пользу.

**3. Уверенный тон не означает правоту.** Ассистент может ровным, убедительным тоном сообщить неверный факт — например, назвать настройку, которой не существует. Текст ответа не доказательство. Доказательство — проверка результата: запустили, посмотрели, сработало или нет.

Эти три пункта объясняют почти все «странности» первых дней. Дальше — практика: короткий цикл действий, который превращает эту теорию в рефлекс.

## По шагам

1. Откройте claude.ai и начните новый чат.
   Вы должны увидеть: пустое поле ввода, готовое принять текст.

2. Скопируйте промпт из блока «Готово к копированию» ниже и отправьте его.
   Вы должны увидеть: ответ с одним блоком кода (HTML), без лишних объяснений.

3. На рабочем столе создайте папку с именем `mysite`.
   Вы должны увидеть: новую пустую папку `mysite`.

4. Включите показ расширений файлов в проводнике (Windows: «Вид» → «Расширения имён файлов»), затем создайте в папке `mysite` пустой текстовый файл и назовите его `index.html` (не `index.html.txt`).
   Вы должны увидеть: файл `index.html` с иконкой браузера, а не блокнота.

5. Откройте `index.html` для редактирования, вставьте туда код из ответа ассистента, сохраните файл.
   Вы должны увидеть: файл сохранён, размер файла больше нуля.

6. Дважды щёлкните по `index.html`.
   Вы должны увидеть: страница-визитка открылась в браузере.

7. Вернитесь в чат и попросите: «сделай кнопку крупнее и добавь строку с городом».
   Вы должны увидеть: новый блок кода с обновлённой версией.

8. Замените содержимое `index.html` новым кодом, сохраните файл, вернитесь в браузер и нажмите F5.
   Вы должны увидеть: кнопка стала крупнее, появилась строка с городом.

9. Повторите шаги 7–8 ещё два раза с двумя другими изменениями по вашему выбору.
   Вы должны увидеть: страница изменилась ещё дважды, итого 3 изменения внесено.

## Готово к копированию

```
Сделай одностраничный сайт-визитку. Требования: один файл HTML, все стили внутри, без внешних библиотек; тёмный фон, светлый текст, одна колонка по центру; заголовок «[ваше имя]», строка с описанием, кнопка «Написать»; страница открывается двойным щелчком без установки чего-либо. Выдай только готовый код одним блоком, без объяснений.
```

## Типичные ошибки

- Файл открывается в блокноте, а не в браузере → настоящее расширение файла `.txt`, а не `.html` → включите показ расширений и переименуйте файл в `index.html`.
- Внесли правку, а на странице ничего не изменилось → файл не сохранён или страница не обновлена → сохраните файл заново, затем нажмите F5 в браузере.
- Просите «сделай красиво» и результат разочаровывает → такая формулировка непроверяема, ассистент достраивает её как хочет → пишите конкретно: что именно, где, каким цветом.
- Пытаетесь понять, как устроен код, в первый день → это рано, задача дня — не код, а цикл «попросил → вставил → проверил» → отложите разбор кода на потом.
- Ответ ассистента оборвался на середине кода → достигнут лимит длины одного ответа → напишите «продолжи с того места, где остановился».

## Задание и критерии приёмки

- [ ] Собрана страница-визитка в файле `index.html`.
- [ ] Страница открывается двойным щелчком без установки программ.
- [ ] На странице есть заголовок, описание и кнопка.
- [ ] Внесено не менее 3 изменений через промпты.
- [ ] Вы можете своими словами назвать, что именно просили изменить на каждом шаге.
- [ ] Вы не пытались разобраться в устройстве кода — это задача другого дня.

## Если не получилось

- Ассистент выдал несколько отдельных файлов вместо одного → напишите: «собери всё в один файл HTML, стили внутри».
- Страница открылась, но она пустая → код скопировался не полностью → скопируйте код заново, целиком, включая первую и последнюю строку.
- Хочется бросить, потому что не получается с первого раза → это нормально для первого дня, так проходят почти все → пройдите шаги ещё раз строго по порядку, не пропуская.
- Не понимаете, куда вставлять код → откройте `index.html` не двойным щелчком (это откроет браузер), а через «Открыть с помощью» → «Блокнот», вставьте туда код, сохраните.

## Самопроверка

10 вопросов, чтобы проверить понимание. Это самопроверка, не экзамен — не блокирует переход дальше.

**1. Почему ассистент «забывает» договорённости из начала длинного разговора?**
- А) Устаёт
- Б) Видит ограниченный объём текста, старое перестаёт помещаться
- В) Экономит ресурсы
- Г) Помнит только последнее сообщение
<details><summary>Ответ</summary>Правильный: Б. Контекст — рабочий стол, а не память.</details>

**2. Вы не указали цвет кнопки. Что произойдёт?**
- А) Ассистент спросит
- Б) Кнопки не будет
- В) Выберет типичный вариант сам
- Г) Будет ошибка
<details><summary>Ответ</summary>Правильный: В. Модель достраивает, а не уточняет.</details>

**3. Ассистент уверенно назвал настройку, которой нет. Это значит:**
- А) Настройка есть, вы не нашли
- Б) Уверенный тон не гарантирует правоту
- В) Ассистент сломался
- Г) Надо повторить вопрос

**4. Как проверить, что ответ верный?**

**5. Файл открывается в блокноте вместо браузера. Причина:**

- А) Разобраться до конца
- Б) Не читать код, сегодня задача — освоить цикл «попросил → вставил → проверил»

**9. «Ассистент не помнит вас» означает:**
