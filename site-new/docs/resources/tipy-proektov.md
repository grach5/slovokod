Курс учит одной процедуре, не одному типу продукта. Здесь показано, как перенести её на что угодно — доступно в тарифах «Полная» и «Максимум».

## Что не меняется никогда

Какой бы продукт вы ни собирали, процедура одна и та же:

```
1. Задание из шести блоков
2. Разбивка на 5–7 проверяемых шагов
3. Файл проекта в начало каждого нового чата
4. Точка возврата перед каждым изменением
5. Один шаг — одна проверка
6. Секреты в переменных окружения
7. Отладка по фактам, а не по ощущениям
8. Чек-лист перед тем, как показать людям
```

Меняются только три вещи:

| Что меняется | Пример |
|---|---|
| **Где живёт продукт** | на сайте, в мессенджере, в браузере, на сервере по расписанию |
| **Как человек к нему обращается** | открывает ссылку, пишет команду, нажимает кнопку, ничего не делает — работает само |
| **Что значит «опубликовать»** | залить на хостинг, зарегистрировать бота, загрузить в магазин расширений, поставить на расписание |

Неправильный вопрос новичка: «а как сделать бота?» Правильный: «где живёт бот, как к нему обращаются и что значит опубликовать бота?» — ответы на эти три вопроса ассистент даёт за пять минут, дальше работает обычная процедура из курса.

## Как выбрать тип под свою идею

**1. Кто и как часто этим пользуется?** Один человек регулярно → инструмент или автоматизация. Много людей изредка → сайт. Много людей регулярно → сайт с личным кабинетом. Никто, работает само → автоматизация по расписанию.

**2. Где эти люди уже сидят?** Идти надо туда, где человек уже есть, а не звать его в новое место. В мессенджере → бот. В браузере на конкретном сайте → расширение. Нигде конкретно → сайт. В таблицах и документах → автоматизация.

**3. Нужно ли что-то сохранять между запусками?** Нет → простой продукт, соберёте за день. Да → нужна база, добавьте день-два.

**4. Есть ли деньги или чужие данные?** Да → сначала безопасность, потом всё остальное. Не наоборот.

## Семь типов

### 1. Сайт

Страница или набор страниц по ссылке в интернете: визитка, лендинг, каталог, сервис записи, личный кабинет. Живёт на хостинге, обращение — по ссылке, публикация — залить на сервис, получить адрес.

Визитка — вечер работы. С формой и сохранением — 2–3 дня. С личным кабинетом — неделя.

Типовые грабли: начали с оформления вместо каркаса; база открыта на чтение всем; не проверили на телефоне. Разобрано в курсе целиком — дни 1–14.

### 2. Телеграм-бот

Продукт, который живёт в мессенджере: приём заявок, уведомления, ответы на частые вопросы, опросы. Работает постоянно на сервере, обращение — команды и кнопки в чате. Публикация — регистрация у официального бота-регистратора, получение токена, запуск на сервере.

Простой бот с кнопками — день. С базой и админ-командами — 3–4 дня.

Типовые грабли: токен в коде — самая частая утечка вообще; бот падает ночью, вы не знаете; не обработан двойной клик по кнопке; нет обработки неожиданного текста.

```
Хочу собрать телеграм-бота. Задача: [что делает].
Я новичок, объясняй по шагам.
Сначала скажи:
— что нужно установить и завести до начала
— где живёт бот и что нужно, чтобы он работал постоянно
— что такое токен и где его хранить
Код пока не пиши.
```

### 3. Автоматизация

Программа без интерфейса, которая делает работу сама: собрать данные, сформировать отчёт, разослать напоминания, следить за изменениями. Работает на компьютере или сервере по расписанию, публикация — поставить на расписание.

Простая обработка таблицы — 2–3 часа. С расписанием и уведомлениями — день.

Правило: любая автоматизация должна сообщать о себе — хотя бы строкой «сделано, обработано 42 записи». Молчаливую автоматизацию нельзя отличить от сломанной.

```
Хочу автоматизировать задачу, которую делаю руками.
Сейчас я делаю так: [по шагам].
Занимает: [время], повторяется: [как часто].

Предложи, как это автоматизировать самым простым способом.
Сначала скажи, что понадобится и какие есть варианты.
Код не пиши.
```

### 4. Расширение для браузера

Дополнение, меняющее или дополняющее чужие сайты: убрать лишнее, добавить кнопку, собрать данные со страницы. Живёт в браузере пользователя. Для себя публикация бесплатна и сразу (папка в режиме разработчика), для других — магазин расширений с проверкой.

Типовые грабли: сайт поменял вёрстку — расширение сломалось (закладывайте поддержку); запрошены лишние разрешения — магазин отклонит.

```
Хочу расширение для браузера. Задача: [что делает]
на сайте [адрес].
Я новичок. Сначала скажи:
— из каких файлов состоит расширение
— как проверить его у себя, не публикуя
— какие разрешения понадобятся и почему
Код не пиши.
```

### 5. Связка сервисов

Моста между чужими сервисами: заявка с сайта уходит в таблицу и мессенджер, оплата запускает выдачу доступа. Срабатывает по событию, публикация — указать адрес обработчика в настройках сервиса-источника.

Правило: связка без журнала неотлаживаема — записывайте каждое событие до обработки, иначе один недоступный сервис теряет данные навсегда.

```
Хочу связать [сервис А] и [сервис Б].
Событие: [что происходит]. Результат: [что должно случиться].

Сначала скажи:
— как сервис А сообщает о событии
— что нужно завести в обоих сервисах
— что делать, если Б недоступен в момент события
Код не пиши.
```

### 6. Внутренний инструмент

Панель для своих: учёт заявок, база клиентов, склад, расписание. Живёт на сайте за паролем, закрытая часть обязательно проверяется на сервере, не только в форме.

Простой учёт — 3–5 дней. С ролями и правами — от двух недель.

Правило: инструмент без выгрузки в таблицу не приживается — люди всё равно заведут параллельную таблицу. Дайте выгрузку сразу.

### 7. Приложение на телефон

Сайт, который ставится на домашний экран и работает как приложение — с иконки, без интернета, с уведомлениями. Публикация — то же, что сайт, плюс файл описания и иконки.

Честно про ограничения: это не заменяет настоящее приложение из магазина, часть возможностей телефона недоступна (особенно на iPhone). Для большинства задач малого бизнеса — хватает.

## От идеи к типу

- «Хочу автоматизировать свою работу» → автоматизация. Начните с самого повторяющегося действия, а не с самого раздражающего — первое даёт результат за вечер, второе за неделю.
- «Хочу продавать услугу» → сайт + бот для уведомлений, но не одновременно: сначала сайт с сохранением, потом уведомления отдельным днём.
- «Хочу инструмент для команды» → внутренний инструмент, но начните не с базы, а с одного экрана со списком — половина задач закрывается списком с фильтром.

### Универсальный запрос для любой новой идеи

```
Хочу собрать: [идея своими словами].

Я прошёл курс «Словокод» по сборке продуктов с ИИ.
Умею: задание, разбивку на шаги, работу с репозиторием,
публикацию, базу, переменные окружения, отладку.

Скажи по этой идее:
1. Какой тип продукта тут подходит и почему
2. Где он живёт и что значит «опубликовать» для него
3. Что нужно завести или установить до начала
4. Разбей на 5–7 проверяемых шагов
5. Что в этом типе продукта ломается чаще всего

Код не пиши. Сначала это.
```

Этот запрос заменяет отдельный курс по конкретному типу продукта: вы прямо перечисляете, что уже умеете из «Словокода», и получаете не обучение с нуля, а только разницу.

## Чего не брать первый год

Честно, чтобы вы не потратили месяц и не решили, что дело в вас:

- **Приложение для App Store / Google Play** — другие инструменты, платные аккаунты разработчика, проверка при каждом обновлении.
- **Игры** — кажутся простыми, устроены сложнее всего остального в этом списке.
- **Продукты с оплатой внутри** — приём платежей это договоры и ответственность за чужие деньги; начните с оплаты по ссылке из стороннего сервиса.
- **Работа с чужими персональными данными в объёме** — медицинские, финансовые, детские данные требуют отдельного оформления по закону.
- **Всё, где ошибка стоит здоровья или больших денег** — расчёт дозировок, конструкций, налогов.

Это не «никогда». Это «не первым проектом».
